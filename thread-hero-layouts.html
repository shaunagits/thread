Thread · hero layout · three options · 14 Aug 2026

Where the graphic goes.

Three ways to fit the animated graphic into the hero. Same copy, same buttons, same margin note, same drawing. Each frame is 1280 wide with the fold marked at an 800px viewport, which is a 13 inch laptop with browser chrome.

A. Below, full width

What is live right now

The graphic spans the whole 1100px content area, so the 900 unit drawing is scaled up about 1.22 times. Tiles land at roughly 54px and the hairlines thin out slightly. The copy block and the margin note sit above it, which pushes the graphic almost entirely below the fold on a laptop.

The problem this creates: the entry animation runs on load, and on a 800px viewport almost nobody sees it. The rotating icons still work whenever the visitor scrolls, but the one-time draw is spent before it is seen.

Copy left, narrow composition right

What I would do

C. The graphic animates on load and rotates continuously. Both of those are wasted if it sits below the fold, which is where A and B put it. C is also the only one that shows a visitor what Thread does before they have read a word.

If the margin rail is not negotiable, B. It is a two line change from what is live and it fixes the scaling, which is the one thing A gets plainly wrong.

Not yet handled in these mockups: C needs a collapse rule below 1000px, where the doc grid already goes single column. The graphic would stack under the copy and keep the narrow composition, which is what it does on a phone today.
